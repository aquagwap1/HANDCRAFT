# Техническое задание
## Разработка веб-платформы продажи товаров ручной работы

### 1. Цель проекта

Разработать веб-платформу, на которой мастера смогут размещать собственные изделия ручной работы, а покупатели — просматривать каталог, добавлять товары в корзину и оформлять заказы без онлайн-оплаты.

Платформа должна упростить взаимодействие между мастерами и покупателями, предоставить удобный каталог изделий и систему управления заказами.

### 2. Технологический стек

- **Frontend:** React — создание пользовательского интерфейса.
- **Backend:** Node.js + Express — обработка запросов и бизнес-логика.
- **База данных:** PostgreSQL — хранение информации.
- **Язык программирования:** JavaScript.
- **Редактор кода:** Visual Studio Code.
- **Система контроля версий:** Git и GitHub.

### 3. Роли пользователей

В системе предусмотрено три основные роли.

**3.1. Покупатель**
- Регистрация и вход в аккаунт.
- Просмотр каталога товаров.
- Просмотр подробной информации о товаре.
- Добавление товаров в корзину.
- Изменение количества товаров в корзине.
- Оформление заказа без онлайн-оплаты.
- Просмотр истории своих заказов.

**3.2. Продавец (мастер)**
- Вход в личный кабинет продавца.
- Добавление новых товаров.
- Загрузка фотографий изделий.
- Редактирование информации о товарах.
- Изменение количества товаров в наличии.
- Просмотр поступивших заказов.
- Принятие и отклонение заказов.
- Изменение статуса заказа.

**3.3. Администратор**
- Просмотр списка пользователей.
- Управление пользователями.
- Просмотр опубликованных товаров.
- Модерация и удаление товаров.
- Управление категориями товаров.
- Контроль работы платформы.

### 4. Функциональные требования

Система должна обеспечивать:

- Регистрацию и авторизацию пользователей.
- Разделение пользователей по ролям.
- Отображение каталога изделий.
- Просмотр отдельных карточек товаров.
- Добавление, редактирование и удаление товаров продавцом.
- Загрузку фотографий товаров.
- Управление остатками товаров.
- Добавление товаров в корзину.
- Оформление заказов без онлайн-оплаты.
- Обработку заказов продавцами.
- Модерацию товаров администратором.

### 5. Разделение функций по приоритету

#### 5.1. MVP — обязательно

1. Регистрация и авторизация пользователей.
2. Разделение пользователей на покупателей, продавцов и администраторов.
3. Просмотр каталога товаров.
4. Просмотр подробной информации о товаре.
5. Добавление и редактирование товаров продавцом.
6. Загрузка фотографий товаров.
7. Управление количеством товаров в наличии.
8. Корзина покупателя.
9. Оформление заказа без онлайн-оплаты.
10. Просмотр и изменение статусов заказов.

#### 5.2. Если останется время

- Система отзывов и рейтингов.
- Добавление товаров в избранное.
- Поиск и фильтрация товаров.
- Система уведомлений.
- Расширенная статистика продаж.
- Личный чат между покупателем и продавцом.

### 6. Страницы сайта

1. **Главная страница** — описание платформы, популярные товары и категории.
2. **Каталог товаров** — список всех доступных изделий.
3. **Страница товара** — фотографии, описание, цена, продавец и остатки.
4. **Страница регистрации и авторизации** — создание аккаунта и вход.
5. **Корзина** — выбранные товары и общая стоимость.
6. **Оформление заказа** — контактные данные покупателя и подтверждение заказа.
7. **Личный кабинет покупателя** — история и статусы заказов.
8. **Личный кабинет продавца** — управление товарами и заказами.
9. **Панель администратора** — управление пользователями, товарами и категориями.

### 7. Структура базы данных

Для работы платформы используется PostgreSQL.

#### 7.1. Таблица users

Хранит информацию о пользователях.

- id — уникальный идентификатор.
- name — имя пользователя.
- email — электронная почта.
- password_hash — хеш пароля.
- role — роль пользователя.
- created_at — дата регистрации.

#### 7.2. Таблица categories

Хранит категории товаров.

- id — уникальный идентификатор.
- name — название категории.
- description — описание категории.

#### 7.3. Таблица products

Хранит информацию о товарах.

- id — уникальный идентификатор.
- seller_id — идентификатор продавца.
- category_id — идентификатор категории.
- name — название товара.
- description — описание.
- price — цена.
- stock — количество в наличии.
- status — статус публикации.
- created_at — дата добавления.

#### 7.4. Таблица product_images

Хранит фотографии товаров.

- id — уникальный идентификатор.
- product_id — идентификатор товара.
- image_url — путь к фотографии.

#### 7.5. Таблица orders

Хранит информацию о заказах.

- id — уникальный идентификатор.
- buyer_id — идентификатор покупателя.
- total_price — общая стоимость.
- status — статус заказа.
- contact_name — имя получателя.
- contact_phone — номер телефона.
- delivery_address — адрес доставки.
- created_at — дата оформления.

#### 7.6. Таблица order_items

Хранит состав заказов.

- id — уникальный идентификатор.
- order_id — идентификатор заказа.
- product_id — идентификатор товара.
- quantity — количество.
- price — цена товара на момент заказа.

### 8. Основные API-маршруты

API используется для взаимодействия frontend и backend.

**Авторизация:**
- POST /api/auth/register — регистрация.
- POST /api/auth/login — вход.
- GET /api/auth/me — получение информации о текущем пользователе.

**Товары:**
- GET /api/products — получение списка товаров.
- GET /api/products/:id — получение информации о товаре.
- POST /api/products — добавление товара.
- PUT /api/products/:id — редактирование товара.
- DELETE /api/products/:id — удаление товара.

**Категории:**
- GET /api/categories — получение категорий.
- POST /api/categories — добавление категории администратором.

**Заказы:**
- POST /api/orders — оформление заказа.
- GET /api/orders/my — получение заказов покупателя.
- GET /api/seller/orders — получение заказов продавца.
- PATCH /api/orders/:id/status — изменение статуса заказа.

**Администрирование:**
- GET /api/admin/users — список пользователей.
- PATCH /api/admin/products/:id/moderation — модерация товара.

### 9. Требования к безопасности

- Пароли пользователей должны храниться в виде хешей.
- Доступ к функциям должен зависеть от роли пользователя.
- Продавец может управлять только собственными товарами и заказами.
- Покупатель может просматривать только собственные заказы.
- Административные функции должны быть доступны только администратору.
- Сервер должен проверять входящие данные.
- Необходимо защищать API от несанкционированного доступа.

### 10. Ограничения проекта

- Онлайн-оплата не предусмотрена.
- Мобильное приложение не разрабатывается.
- Проект создаётся как веб-сайт.
- Все основные функции реализуются в рамках одного веб-приложения.
- Дополнительные возможности могут быть реализованы после завершения MVP.

### 11. Ожидаемый результат

Готовая веб-платформа, позволяющая мастерам размещать изделия ручной работы и управлять заказами, покупателям — просматривать каталог и оформлять заказы, а администратору — модерировать товары и контролировать работу платформы.
